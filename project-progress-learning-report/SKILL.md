# 项目进度与学习验收汇报

用简体中文按六部分汇报。用户同时需要掌握项目进度、亲自评测功能和理解代码，技术说明保持中等详细度：不能只列术语，也不要展开成长篇教程。

## 先核实事实

- 读取项目协作规则、交接记录、当前任务包，按需要查看实际代码和测试证据。区分实现者自报、独立审核、用户亲测。
- 不把方案通过说成代码完成，不把代码完成说成真实调用通过，不把上传 Git 说成上线，不把待开工说成正在开发。
- 不为写汇报自动启动服务、运行测试、提交代码或联系其他人；这些动作沿用会话授权和项目规则。
- 定时检查无变化时遵守静默要求，不强制输出六部分。普通小问答简短回答；整体进度和阶段交付采用本格式。

## 汇报规则

- 从模板中读取固定六部分结构及各表格列；顺序固定，表格保持简洁，不重复同一解释。
- 项目进度按产品、设计、研发、测试、用户验收、交付发布展示，不能用技术模块代替项目流程。百分比注明范围和计算依据；没有依据则用状态。计划时间与实际时间分开。
- 产品功能站在用户视角描述真实功能、演示能力、部分实现、未实现，并标记本期涉及的功能。
- 技术架构依项目实际列出，区分业务对象状态机与任务执行状态机、能力函数与统一 Skill 调度、预设导航与 Agent 编排。
- 学习点用一至两句话解释概念并联系本项目行为。需要学习代码时提供真实文件链接及观察方法；尚未实现的位置标为计划。
- 测试与验收区分已测、未测、独立审核和用户亲测。提供实际可用地址；服务未启动时明确待提供。测试通过数量附来源，不把历史结果算成本期结果。
- 下一步区分已授权工作和候选建议，不能把未来建议自动变成开工指令；指出负责人、完成标志及必要依赖。

## 模板选择

1. 用户指定模板时使用指定模板；否则读取 `config/current_template.txt` 中的默认模板名。
2. 加载 `templates/` 中同名 Markdown 文件，按其中的六部分结构汇报；完整内容以用户最新要求为准。
3. 模板文件使用语义化名称；停用模板移至 `templates/archive/`，正常维护时不删除。

## 表达与记录

- 敏感配置只报告是否配置，不输出密钥或真实个人资料。
- 项目已有交接和验收文件时，按任务授权维护状态与用户待测项；报告模板本身不授权改写契约或扩大研发范围。
- 首次建立项目时间轴后保持口径稳定；范围改变时解释变化，不能静默重置阶段或百分比。
